# 免费游戏素材选型

## 筛选

- 明确素材在游戏里的用途，以及项目的引擎、素材格式、美术方向和发行方式。把必须满足的条件与偏好分开。团队还没决定是否商用时，优先找允许商用的选项并注明这个假设。
- 从 [Free Game Dev Assets](https://github.com/TMHSDigital/Free-Game-Dev-Assets) 找候选。项目需要一组搭配资源时可从上游 starter stacks 入手。目录查询与字段说明见 [素材目录用法](references/catalog.md)。目录没覆盖时，再查创作者或发行平台的一手来源。
- 结合实际用途判断合适程度，例如像素网格、视角和帧数，3D 骨架与动画兼容性，字体是否覆盖目标语言，音频能否无缝循环。引擎筛选结果只用于初筛，格式适配与引擎授权分别核对。

## 核验

- 对最终候选打开原作者或发行方的具体素材页和许可文本，确认下载版本或免费档实际适用的条件。目录的 verified 字段只表示上游读取许可的日期，和本次核对日期分开记录。聚合站逐个文件核对。若证据缺失、条款冲突或免费档不明确，把未解决的问题写入结果。
- 根据用途核对商用、修改、署名及随包许可文件。发布游戏成品、在公开仓库托管素材源文件、发行可提取素材的模板或模组是不同的使用场景，按用户实际需要查证。免署名也可能要求随包附带许可。遇到引擎独占、自定义条款或限额时核对具体条款。工具的许可按实际使用方式核对，区分用工具制作素材和把代码、运行时或生成内容随游戏发行。
- 仅在具体候选的许可已核对、且符合用户的使用方式时，标记为可用于该场景。遇到不确定的候选时，说明仍需确认什么，并在有匹配项时优先给出许可明确的选项。

## 交付

- 按项目需求给精简候选，每项列出具体素材、作者或发行方、原始获取页、许可原文链接、核对日期、相关义务及关键兼容性信息。只有在实测后才标记为已验证可导入。找整组素材时检查画风、尺寸规格和使用条件能否一起成立。
- 用户要求引入素材时，保留选定版本、来源链接和原始许可文件，沿用项目的第三方素材记录或 Credits 约定。如需署名，写入实际作者、素材名、链接和许可，并按条款标明修改。仅找素材或评估许可时，直接交付候选和证据。
